# Common Tester 구현 기록: 6단계 React 검토 화면

## 목표

- 브라우저 화면에서 실행 생성부터 계획 검토, 승인 또는 거절, 결과 확인까지 진행한다.
- 테스트 단계와 기대 결과 옆에 정책 원문을 보여 사람이 계획의 타당성을 판단할 수 있게 한다.
- 실패한 테스트의 화면 이미지와 Playwright 추적 파일을 실행 상세에서 연다.

## 구현한 경로

| 파일 | 내용 |
| --- | --- |
| [App.tsx](../../web/src/App.tsx) | 실행 목록, 검사 목표, 계획과 근거, 승인·거절, 결과 표시 |
| [style.css](../../web/src/style.css) | 작업 화면과 모바일 레이아웃 |
| [main.py](../../api/app/main.py) | 데모 정책 등록과 실행별 증거 파일 조회 API |
| [check_stage6.py](../../api/check_stage6.py) | 실제 DB와 Playwright로 정책 등록 및 증거 파일 조회 검사 |
| [check_stage6_ui.py](../../web/check_stage6_ui.py) | 모의 API와 Chromium으로 화면 전체 흐름 검사 |

## 화면에서 처리하는 순서

1. 기본값인 `demo-orders`, `/fixtures/order.html`, `v1`로 실행을 만든다. 이때 서버의 `POST /api/demo/setup`이 저장소의 예시 주문명 정책을 등록한다. 같은 정책을 다시 등록해도 중복 문단이 생기지 않는다.
2. 검사 목표를 입력하고 `계획 생성`을 누른다. 서버의 LangGraph 흐름이 계획을 만들고 검토 지점에서 멈춘다.
3. 화면에서 각 테스트의 입력·클릭 단계, 기대 결과, 정책 원문을 확인한다. 정책 원문이 로드되지 않으면 승인 버튼을 사용할 수 없다.
4. `승인하고 실행`을 누르면 브라우저 검사 결과가 표시된다. `계획 거절`을 누르면 검사 없이 끝난다.
5. 실패한 테스트는 오류와 함께 화면 이미지 및 Playwright 추적 파일 링크를 보여준다. 서버는 해당 실행의 결과에 기록된 파일만 제공한다.

목록에서 과거 실행을 선택하면 저장된 계획과 결과를 다시 볼 수 있다. 현재 자동 계획 생성은 등록된 데모 주문 화면만 지원한다.

## 검증 결과

- `npm run build`: TypeScript 검사와 Vite 프로덕션 빌드 통과.
- `python api/check_stage6.py`: 예시 정책 중복 등록, 결함 화면 실패, PNG 및 ZIP 파일 조회, 결과에 없는 파일의 404 응답 확인.
- `python web/check_stage6_ui.py`: Chromium에서 실행 생성, 계획과 정책 원문 확인, 승인 후 2건 통과 표시, 다른 실행의 거절 표시 확인.
- 390px 모바일 폭에서도 가로 넘침이 없음을 확인하고 화면을 시각 점검했다.

API와 DB를 `scripts/start-api.ps1`로 시작하고, `web`에서 `npm run dev`로 화면 서버를 시작한 뒤 검사를 실행한다.

## 남은 범위

- 실제 모델 호출은 아직 새 로컬 API 키로 검증하지 않았다. 키 없이 계획 생성 버튼을 누르면 설정 안내가 표시된다.
- 화면의 승인 판단은 사용자 몫이다. 현재 서버 검증은 계획의 형식과 근거 ID·버전까지 확인한다.
- 7단계에서 실패 유형별 품질 검사와 평가 데이터를 추가한다.
