# Common Tester 구현 기록: 7단계 품질 평가

## 목표

- 정책 검색, 실행계획 검증, 실제 브라우저 판정을 고정된 정답 데이터로 반복 측정한다.
- 정책 근거 ID만 맞고 기대 문구를 지어낸 계획을 검토 전에 차단한다.
- 정적 검사로 알 수 없는 화면 결함과 상황에 맞지 않는 기대값은 브라우저 실행에서 실패로 드러나는지 확인한다.

## 구현한 경로

| 파일 | 내용 |
| --- | --- |
| [golden.json](../../examples/eval/golden.json) | 검색 질문 24개, 계획 판정 16개, 브라우저 시나리오 17개의 정답 데이터 |
| [evaluate.py](../../api/evaluate.py) | API를 통한 평가 실행, 사례별 판정과 JSON 보고서 생성 |
| [validation.py](../../api/app/validation.py) | 데모 화면의 문자 그대로 비교하는 기대 문구가 정책 원문 또는 등록된 화면 코드에 있는지 확인 |
| [generator.py](../../api/app/generator.py) | 등록된 코드 파일을 `code:order_form` 근거 ID와 함께 모델에 전달 |

## 평가 방식

1. 예시 정책을 등록하고 질문 24개에 대해 기대 문단의 Top-1, Top-3와 프로젝트·버전 격리를 검사한다. Top-1 목표는 90%다. 등록되지 않은 프로젝트와 버전 검색은 빈 결과여야 한다.
2. 정상 계획, 허위 근거, 버전 불일치, 잘못된 필드 참조, 중복 ID, 지원하지 않는 동작, 잘못된 위치 지정자 등 16개 계획을 API에 보낸다. HTTP 상태와 알려진 오류 문구를 정답과 비교한다.
3. 정상 저장, 빈 값, 공백 값, 한글과 이모지, 20자·21자 경계, Enter 제출, CSS 위치 지정자, 결함 화면, 모순된 기대값, 없는 요소를 포함한 17개 시나리오를 Python Playwright로 실행한다.
4. 결과는 `.local/evaluations/stage7-latest.json`에 사례별로 남긴다. 모든 기대와 일치하지 않으면 평가 스크립트가 종료 코드 1을 반환한다.

## 이번 측정 결과

| 구간 | 결과 | 확인한 내용 |
| --- | --- | --- |
| 정책 검색 | Top-1 24/24, Top-3 24/24 | v1 20문항, v2 4문항. 미등록 프로젝트와 버전 격리 확인 |
| 계획 검증 | 16/16 | 유효 계획 수락, 허위 문구와 근거, 스키마·참조 오류 거부 |
| 브라우저 시나리오 | 17/17 일치 | 입력 경계와 필수값 통과, 결함과 모순된 계획 탐지 |
| Playwright 케이스 | 20개 실행 | 16개 통과, 4개 실패. 실패 4개는 의도한 오류 검출 |
| 회귀 검사 | 통과 | 5단계 LangGraph 보정, 승인, 재개 흐름 유지 |

이번 평가는 브라우저 시나리오 17개에서 Playwright 테스트 케이스 20개를 실행했다. 16개는 통과했고 4개는 실패했다. 실패 4개는 결함 화면, 모순된 기대값, 존재하지 않는 요소에서 예상된 탐지 결과다. 모델이 새로 생성한 테스트는 0개이며 저장소의 고정 계획 예시를 사용했다.

정책 원문이나 등록된 페이지 코드에 없는 `text` 기대 문구는 이제 422로 거부한다. 코드 근거 ID도 등록된 `code:order_form`만 허용한다. 이 문구 검사는 현재 자동 생성 대상인 데모 주문 화면에만 적용한다. 반대로, 문구가 출처 어딘가에 있어도 해당 입력 상황에 맞는지는 이 검사만으로 판정할 수 없다. 정답 데이터의 “상황에 맞지 않는 기대값”은 계획 저장에는 통과했지만 실제 브라우저에서는 실패했다.

## 실행 방법

전용 API와 DB를 `scripts/start-api.ps1`로 시작한 뒤 저장소 루트의 다른 PowerShell 창에서 실행한다.

```powershell
.\.venv\Scripts\python.exe api\evaluate.py
```

실제 모델이 만든 실행 ID가 있을 때는 `--run-id <ID>`를 붙여 그 계획의 21자 경계 사례 포함 여부, 생성 시도와 토큰 수, 실행 상태를 같은 보고서에 추가할 수 있다. 모델 API 호출 자체는 이 평가 스크립트가 수행하지 않는다.

## 해석과 남은 범위

- 24개 검색 질문, 16개 계획 사례, 17개 브라우저 시나리오는 자체 제작한 데모 집합이다. 이 수치를 일반적인 검색 정확도나 모델 품질로 해석하지 않는다.
- 실제 모델 생성 계획의 품질 점수는 새 로컬 API 키로 호출한 실행이 없어 아직 없다.
- 기대 문구의 출처 포함 여부는 문자 그대로 비교한다. 숫자에서 도출한 문구, 동적 텍스트, 문맥상 함의를 이해하는 검사는 아니다. 이런 경우에는 화면에서 사람이 근거와 계획을 검토해야 한다.
- 다음 8단계에서 최종 실행 환경과 제출 자료를 확인한다. Docker 이미지와 Kubernetes는 사용자가 지정한 최종 확인 시점에 다룬다.
