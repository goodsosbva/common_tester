# 2단계: 근거 검색과 전달 명세

## 구현

- `retrieve_evidence`: 제품/버전의 SQLite 임베딩을 이용해 요구사항을 찾고, 저장된 원문 조각과 문서 경로·문단 번호·조각 번호를 함께 가져온다.
- `build_handoff`: 검색된 원문 근거를 OpenAI API에 전달해 Playwright 코드 생성용 JSON을 만든다.
- LangGraph: `START → retrieve_evidence → build_handoff → END`
- 벡터는 검색에 쓰고, API에는 해석할 수 있는 원문 근거를 보낸다. 벡터를 원문처럼 보내거나 전체 원문을 무조건 전송하지 않는다.
- 입력 원문과 임베딩 해시가 다르면 처리를 중단한다.

## 검증 결과와 제한

근거의 요구사항 키 75개와 생성 명세의 키 75개가 일치한다. 생성된 모든 상황의 출처가 해당 제품/버전의 근거 목록에 존재한다. 행동과 관찰 결과가 비어 있거나 출처가 없는 상황은 저장하지 않는다.

원문에 거부 조건이 적혀 있는 일부 요구사항은 거부 상황을 만들었다. 나머지 69행은 표시 항목 나열이나 기능 설명만 있고 거부 조건이 없어 거부 상황을 임의로 만들지 않았다. 관찰 결과나 판정 기준도 원문에 없으면 `unresolved`로 남긴다. 따라서 이번 결과는 전체 요구사항을 빠짐없이 전달하지만, 모든 요구사항에서 허용·거부 상황을 모두 만들었다는 뜻은 아니다. 원문에 기준이 추가되면 해당 버전을 갱신하고 다시 임베딩해야 한다.

## 호출 방법

`POST /api/handoffs`에 제품, 버전, 로컬 테스트 주소와 검사 범위를 전달한다. 전체 제품 검사는 `scope`를 `전체`로 지정한다.

    {
      "product": "product",
      "version": "v1",
      "target_url": "http://127.0.0.1:8765/product-demo.html",
      "scope": "전체"
    }

실행별 결과는 `.local/runs/<실행ID>/evidence.json`과 `.local/runs/<실행ID>/test-spec.json`에 저장한다. 이 명세가 3단계 Codex Playwright 생성 입력이다. 3단계 코드는 아직 생성하지 않았다.
