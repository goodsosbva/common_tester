# Common Tester 구현 기록: 9단계 테스트 수 지정과 화면 캡처

## 변경 이유

- 기존 생성 지시문이 목표 하나당 테스트를 1~2개만 만들도록 제한했다.
- 실행 결과 화면은 실패 사례에 대해서만 저장하고 성공 사례는 남기지 않았다.

## 구현

- 새 실행 화면에서 생성할 테스트 수를 1~30개로 지정한다. 기본값은 20개다.
- 데모 주문 화면에 수량, 금액, 메모 입력을 추가하고 네 정책 문서를 등록한다. 기존 주문명 검사는 기본값 수량 1, 금액 0으로 계속 실행할 수 있다.
- 생성 지시문에 목표 개수와 사례 다양성을 전달한다. 근거가 없는 정책값은 만들지 않도록 기존 제한을 유지한다.
- 계획 검증에서 목표 개수와 실제 개수가 다르면 LangGraph가 한 번 보정한 뒤 다시 검증한다.
- Playwright는 성공과 실패 사례 모두 최종 화면을 `.local/runs/<run-id>/case-<번호>.png`로 저장한다.
- 각 사례 카드에서 성공 또는 실패 캡처를 미리 보고 원본 이미지도 연다. 실패 trace 제공은 유지한다.

## 범위와 한계

- 30개는 생성 요청의 상한이다. 정책과 화면 근거가 좁으면 서로 다른 유효 사례 20개를 만들 수 없는 경우가 있다. 이때 모델의 보정도 같은 근거 한계에 막힐 수 있다.
- 이 변경은 실행 사례별 캡처를 저장한다. 계획 생성이나 거절처럼 브라우저를 실행하지 않은 상태에는 캡처가 없다.
- 실제 모델이 데모 주문 폼에서 20개를 생성하고 실행하는 결과를 확인했다. 사례 수와 품질을 다른 화면으로 일반화할 수는 없다.

## 확인 결과

- `npm run build`가 TypeScript 검사와 Vite 빌드를 통과했다.
- 로컬 Chromium에서 정상 계획 2건과 의도한 실패 계획 1건을 실행했다. 세 사례 모두 캡처 파일이 생성됐다.
- 주문 수량 0, 소수, 재고 초과, 음수 금액, 메모 201자, 정상 경계값 등 추가 화면 시나리오 6건을 확인했다.
- 로컬 API에서 기존 정상 계획 2건과 결함 계획 1건을 다시 실행했다. 네 정책 문서가 등록됐고, 성공 캡처 2건과 실패 캡처 1건 모두 이미지 API에서 열렸다.
- [정책별 20개 고정 실행계획](../../examples/twenty-case-plan.json)을 API에 저장해 Playwright로 실행했다. 20건 모두 통과했고 사례마다 캡처가 저장됐다. 실행 ID는 `892bbf6f-7a52-43f4-b7a4-df91da8c754e`이다.
- 이 20개 계획은 정책과 화면을 근거로 직접 작성한 검증 자료다. 모델이 생성한 계획의 개수나 품질 점수로 해석하지 않는다.
- 2026-10-26 새 키를 적용한 뒤 모델이 계획 20개를 생성했다. 정책 검색과 화면 확인 도구를 사용했고 Playwright 실행에서 20/20 통과했다. PNG 20장이 저장됐다. [실제 실행 기록](live-model-result.md)에 사례별 결과가 있다.
