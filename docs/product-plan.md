# 제품 기획과 요구사항 정리

## 원본과 사용 원칙

- 기준 원본: documents/product/v1/제품_요구사항_정의서.pdf
- PDF 9쪽의 요구사항 75행을 읽었다. 고유 ID는 74개다.
- documents/product/v1/requirements.md는 PDF 표의 ID, 이름, 상세, 쪽수와 표 행을 보존한 검색 자료다. 내용이 다르면 PDF를 기준으로 확인한다.
- 폴더의 v1은 Common Tester에서 구분하기 위해 붙인 버전명이다. PDF에 명시된 제품 버전이라는 뜻이 아니다.
- 미확정 검토 메모는 docs/product-uncertainties.md에 두며 검색 근거에는 넣지 않는다.
- 원문에 없는 입력 경계, 오류 문구, 성공 조건, 추천 알고리즘은 만들지 않는다. 아래 미확정 항목은 판정 근거가 확정될 때까지 테스트 명세에서 보류한다.

두 행은 별개의 원본 요구사항으로 유지한다. 요구사항 ID만으로 하나를 선택하지 않고 PDF 쪽수와 행, 검색 문서의 문단과 조각 위치를 함께 사용한다.

## 테스트 생성에 적용할 기준

1. 요구사항 ID와 원문 위치를 명세에 함께 기록한다.
2. 원문에 적힌 허용 조건과 거부 조건만 테스트 상황으로 확정한다.
3. 반대 상황이나 화면 판정 신호가 PDF에 없다면 미확정으로 남긴다.
4. 원본 PDF와 검색용 문서의 위치를 결과 화면에서 추적할 수 있게 한다.
5. order-demo는 별도 예제 자료다. 제품 전체 기획의 대체 문서로 사용하지 않는다.
